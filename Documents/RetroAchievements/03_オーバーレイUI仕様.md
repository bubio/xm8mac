# オーバーレイUI仕様

## 1. UI原則

- RA固有画面はすべて既存SDLウィンドウ内へ描画する。
- 描画基準は既存フレームバッファと同じ640x400論理解像度とする。
- OS固有UIはAndroid SAF選択とOS権限確認だけに限定する。
- RA画面はキーボード、ゲームコントローラ、マウス、タッチだけで完結させる。
- RA通信や画像取得を待つ間も描画と入力を止めない。
- UI文字列をRA APIの英語エラーから直接作らず、安定したmessage keyから生成する。
- RA由来文字列は内部で検証済みUTF-8として保持し、byte数ではなくUnicode code pointと
  描画glyph幅で省略・scroll位置を計算する。

### 1.1 文字描画

初期実装では新しいOS font APIやSDL_ttfを追加せず、既存KANJI ROM描画を利用する
`RaTextRenderer`を追加する。

- UTF-8を厳密にdecodeし、overlong、surrogate、不正continuation、途中終端を拒否する。
- Unicodeから既存Shift-JIS glyphへ変換できる文字だけを描画する。
- 4-byte UTF-8、Shift-JIS非対応文字、KANJI ROMにない文字は`?`へ1文字ずつ置換する。
- 変換は固定長bufferへ無制限に書かず、出力上限付きAPIとする。
- DBとログには置換前の検証済みUTF-8を保持する。
- username、title、descriptionの不正UTF-8はresponse全体を破棄せず、当該文字列を
  replacement表示して診断ログへ件数だけを記録する。

## 2. 描画レイヤー

描画順序を次に固定する。

1. VM映像
2. 既存ステータス行
3. 既存ソフトキー
4. RA Challenge IndicatorとLeaderboard tracker
5. RA toast通知
6. RAフルオーバーレイ
7. RA確認ダイアログとオンスクリーンキーボード

- 上位レイヤーだけがポインター入力を受け取る。
- RAフルオーバーレイ表示中はVM入力を遮断する。
- Hardcoreで非停止表示している場合もVMへゲーム入力を流さない。
- 通知だけの表示ではVM入力を遮断しない。

現行`Video::Draw()`と`Video::DrawMenu()`はそれぞれ`SDL_RenderPresent()`を行い、
画面変化がない場合に早期returnする。両経路でPresent直前に同じRA合成callbackを呼ぶ。
toast、tracker、画像完了、focus、scroll、時計更新がある間は`RaOverlay::NeedsRedraw()`から
`Video::DrawCtrl()`相当を要求し、VM画面が静止していても表示と消去を反映する。

## 3. レイアウト基準

### 3.1 共通寸法

| 項目 | 論理寸法 |
|---|---:|
| 画面 | 640x400 |
| 外側余白 | 12px |
| ヘッダー | 40px |
| フッター操作列 | 36px |
| 標準行 | 40px |
| 最小タッチ領域 | 40x40px |
| バッジ小 | 32x32px |
| バッジ標準 | 48x48px |
| バッジ詳細 | 72x72px |

- Androidのsystem bar insetはSDL側で取得した安全領域へ反映する。
- 画面比率が異なっても論理座標を伸縮せず、既存映像と同じ変換を使う。
- 文字列が領域を超える場合は末尾省略し、フォーカス時に横スクロールする。
- ボタン幅を文字列に応じてフレームごとに変化させない。

### 3.2 色と状態

- 背景は不透明度の高い中立色とし、VM映像上でも文字コントラスト4.5:1以上を目標とする。
- Hardcoreは警告色と鍵アイコンを併用し、色だけに依存しない。
- 接続状態は`Online`、`Disconnected`、`Offline session`、`Disabled`を文字でも表示する。
- ロック済み実績はグレースケールまたは専用画像を使うが、説明文を読める状態にする。

## 4. ナビゲーション

既存メインメニューのトップ階層へ`RetroAchievements`を1項目追加する。
RAビルド無効時は項目自体を表示しない。

初期実装では、`RetroAchievements`メニュー自体をRAホーム相当の入口として扱い、
独自デザインのRAホームオーバーレイは作らない。既存メニューと同じ描画、入力、
スクロール、Back操作を使う。

Library、Game Detail、Achievements、Leaderboards、Settingsなど、既存メニューだけでは
情報量が足りない画面は`RaOverlay`が画面スタックとして所有する。

```text
RetroAchievements menu
├─ Login / Account
├─ Library
│  └─ Game Detail
│     ├─ Achievements
│     │  └─ Achievement Detail
│     ├─ Leaderboards
│     └─ Media Configuration
└─ Settings
```

- Backは既存メニューまたはRA overlay stackを1段戻す。
- 最上位でBackを押すとメインメニューへ戻る、またはRAオーバーレイを閉じる。
- 非同期処理中でもBackを許可し、関連要求をキャンセルする。
- 実行中ゲームのアンロードを伴う操作は確認ダイアログを出す。

## 5. 入力マッピング

| 操作 | キーボード | Controller | タッチ/マウス |
|---|---|---|---|
| 移動 | 矢印 | D-pad/左stick | スクロール/タップ |
| 決定 | Enter | A | タップ |
| 戻る | Esc/Backspace | B | 戻るボタン |
| タブ切替 | PageUp/PageDown | LB/RB | タブをタップ |
| コンテキスト | Menu | X | 長押し |
| 検索 | Ctrl+F | Y | 検索アイコン |

- Controller表記は実際のSDL button labelへ置換する。
- 長押しだけに必須操作を割り当てず、コンテキストメニューからも実行可能にする。
- タッチスクロール中の指離しを決定操作として扱わない。
- 既存ソフトキーとRAオンスクリーンキーボードを同時表示しない。

## 6. 画面仕様

### 6.1 RetroAchievementsメニュー

表示項目:

- RA有効/無効
- ユーザー名、スコア、アバター
- Softcore/Hardcore
- 接続状態
- 現在のゲーム、ゲームバッジ、Rich Presence
- 解除数/総数、ポイント
- Library、Achievements、Leaderboards、Settings、Logout

未ログイン時はLoginを主要操作とし、ゲーム情報領域を表示しない。
ゲーム未実行時はAchievementsとLeaderboardsを無効表示する。

初期実装では、トップ階層の`RetroAchievements`メニューに`RA mode`、
状態行、`Login/Logout`、`Achievements`、`Leaderboards`を同列に表示する。
Achievementsはロード済みRAゲームの実績一覧オーバーレイを開く。Leaderboardsは
一覧画面の実装完了まで未実装通知を表示するだけにし、独自の中間Home画面は挟まない。
Achievements初期画面は5行単位の一覧、選択枠、上下スクロール、選択項目の説明表示を
持つ。キーボード、コントローラ、マウス、タッチで項目を選択でき、`Esc`または
一覧外クリック/タッチで閉じる。

### 6.2 ログイン

フィールド:

- Username
- Password

動作:

- Passwordは伏字表示し、表示切替アイコンを提供する。
- Login実行中は二重送信を禁止し、pending表示にする。初期実装では
  `rc_client`の非同期login requestを中断せず、完了callbackを待つため、
  Login pending中の`Cancel`、`Esc`、Android Backは無効化する。
- 成功時はパスワードバッファを上書きし、Login画面を閉じる。
- 失敗時はフィールド内容を維持するが、Passwordは消去する。
- 初回成功時はトークン平文保存の説明を確認表示し、了承後に保存する。
- 保存を了承しない場合はログイン成功を取り消してログアウトする。初期版では
  トークンを保存しない一時ログインモードを提供しない。
- ゲーム起動から表示されたLogin画面では`Login`、`Continue without achievements`、
  `Cancel game launch`を別操作として表示する。通常のAccount画面ではoffline継続を表示しない。

### 6.3 オンスクリーンキーボード

- ASCII英数字、RAユーザー名・パスワードで一般的な記号、Shift、Backspace、Space、Doneを持つ。
- Password入力中もキー配列は変えない。
- 物理キーボード入力は`SDL_StartTextInput()`と`SDL_TEXTINPUT`を使う。
- Androidでは入力欄フォーカス時に`SDL_StartTextInput()`を呼び、OSソフトウェア
  キーボードを第一候補にする。入力欄以外へフォーカスが移った場合、または
  Login画面を閉じた場合は`SDL_StopTextInput()`を呼ぶ。
- AndroidのOSソフトウェアキーボードは必須要件にはしない。表示されない端末や
  SDL backend構成でもログイン操作が詰まらないよう、RAオーバーレイ内の
  controller/touch操作とオンスクリーン入力手段を保険として維持する。
- 入力上限はUsername 256 UTF-8 bytes、Password 1024 UTF-8 bytesとする。
- 制御文字、改行、NULを拒否する。

### 6.4 ゲームライブラリ

RetroAchievements Libraryは登録済みRAゲーム一覧であり、表示対象はRA識別済みゲーム
だけとする。未識別媒体、RA未登録媒体、照合エラー、`DISK_A`などの暫定媒体名は
Library v1の一覧に表示しない。対象がない場合は`No RetroAchievements games in library`
を表示する。

一覧行に次を表示する。

- 48x48ゲームバッジ
- RAタイトル
- 解除数/総数
- 最終起動日時
- media healthの短い状態表示

操作:

- 選択ゲームのGame Detail表示

詳細欄にはGame ID、RA Game ID、最終起動日時、media healthを表示する。
初期表示は最終起動日時降順とする。検索、並べ替え、D88/M3U/folder追加、
未識別媒体一覧、診断表示はLibrary v1では実装しない。

### 6.5 ゲーム詳細

上部にゲーム画像、タイトル、RA Game ID、進捗、最終同期、Rich Presenceを表示する。
最小実装ではLibraryで選択中のRAゲームを詳細表示し、RAタイトル、badge、進捗、
Game ID、RA Game ID、最終起動日時、media healthを表示する。LibraryのEnter/クリック/
タップはGame Detailを開き、ゲーム起動はGame DetailのSTARTボタンまたはEnterで行う。
Game DetailのLeft/EscapeでLibraryへ戻る。

操作:

最小実装ではSTARTだけを表示する。STARTは保存済みworking copyからゲームを起動する。
Softcore/Hardcore切替、Achievements、Leaderboards、Media Configuration、Rescan RA、
Remove from Libraryは後続で追加する。

`Remove from Library`は作業コピーを削除するか選択させる。既定は保持とする。
実行中ゲームの`Rescan RA`、削除、媒体移動、作業コピー再作成は無効化し、ゲーム終了後に
実行する。閲覧と同一ゲーム内の明示的ディスク交換だけを許可する。

### 6.6 媒体構成

媒体ごとに次を表示する。

- 表示名
- MD5先頭8文字
- bank数と各bank名
- 原本状態
- 作業コピー状態
- 並び順
- Drive割当
- RA anchor

操作:

- 媒体追加、別ゲームへ移動、順序変更、原本再指定
- Drive 1/2とbankの割当
- RA anchor指定
- 作業コピー再作成
- セーブデータ初期化

セーブデータ初期化は破壊的操作として二段階確認する。
RA Game IDが所属ゲームと異なる媒体は競合表示し、RA anchorとRAディスク交換先へ
指定できない。補助Driveへの割当は許可する。
原本変更を検出した媒体では「既存セーブから起動」と「変更後原本を新規登録」を
別操作で表示し、既存作業コピーを暗黙に置換しない。

### 6.7 実績一覧

`rc_client_create_achievement_list()`が返すbucket順、`label`、`bucket_type`をそのまま使う。
Locked、Unlocked、Unsupported、Unofficial、Recently Unlocked、Active Challenge、
Almost There、Unsyncedなどを独自の固定順へ並べ替えない。未知bucketも非表示にせず
`label`付きで表示する。

各行はバッジ、タイトル、説明、ポイント、解除状態、進捗を表示する。
ロック実績の秘密情報はRAから隠されている範囲を尊重し、推測表示しない。

### 6.8 実績詳細

- 72x72バッジ
- タイトル、説明、ポイント、種別、解除日時
- Softcore/Hardcore解除状態
- 測定可能な場合は現在値と目標値
- レアリティ情報がAPIから提供される場合は表示

### 6.9 Leaderboard

一覧はタイトル、説明、状態、自己ベストを表示する。実行中trackerはゲーム画面上へ
常駐し、開始、失敗、送信時の状態変化をアニメーションなしでも識別できるようにする。

Scoreboardイベントでは順位、送信値、上位エントリを一時表示し、詳細画面から再確認できる。
event内pointerはcallback終了後に保持せず、表示用の最新scoreboardをセッション内履歴へ
deep copyする。履歴はゲーム終了時に破棄する。

一覧の自己ベストは`rc_client_leaderboard_t`だけから取得できないため、詳細を開いた時に
`rc_client_begin_fetch_leaderboard_entries_around_user()`を非同期実行する。未取得、取得中、
取得失敗を別状態で表示する。

### 6.10 RA設定

- RA Enabled
- Last mode: Softcore/Hardcore（初期値Softcore）
- Unofficial achievements: 初期値OFF
- Encore mode: 初期値OFF
- Spectator mode: 初期値OFF
- Notification duration: 3/5/8 seconds、初期値5
- Image cache limit: 64/128/256MiB、初期値128
- Clear image cache
- Saved data management（ライブラリから分離して保持した作業コピー）
- Logout

モード設定以外はゲーム実行中に変更可能とする。ただし`rc_client`上、ロード時にしか
評価されない設定は「次回起動から適用」と表示する。

## 7. 通知仕様

通知は優先度キューで管理する。

| 優先度 | イベント |
|---:|---|
| 3 | 実績解除、Game/Subset completed、Hardcore解除につながる警告 |
| 2 | Leaderboard結果、ゲーム識別、切断、サーバーエラー |
| 1 | 進捗、Challenge、Leaderboard tracker更新 |
| 0 | 画像取得失敗等の非致命情報 |

- 同時toastは最大3件とし、それ以上はキューへ保持する。
- 同じ接続エラーを連続表示せず、状態変化時だけ通知する。
- 実績解除toastはバッジ、タイトル、ポイント、Hardcore状態を表示する。
- 通知時間中にオーバーレイを開いても消失させず、復帰後に残り時間を再開する。
- ゲーム終了時は未表示通知を破棄する。ただし送信中エラーはRetroAchievementsメニューへ
  履歴を1件残す。

## 8. Challengeとtracker配置

- Challenge Indicatorは右上から縦方向へ並べる。
- Leaderboard trackerは左上へ配置する。
- toastは右下、既存ステータス行とソフトキーの上へ配置する。
- 画面幅不足時はChallengeをアイコンだけに縮小し、trackerを優先する。
- 配置領域が重なる場合はtracker、Challenge、toastの順に保持し、toastを次へ送る。

## 9. 画像処理

- URLは`rc_client_*_get_image_url()`または構造体の公式URLから取得する。
- URL helperが`RC_INSUFFICIENT_BUFFER`を返した場合は必要量を上限4KiBまで拡張して再試行し、
  固定長bufferで切り詰めない。
- HTTP完了後、ワーカースレッドで`stb_image`によりRGBAへデコードする。
- SDLテクスチャ作成またはフレームバッファ変換はメインスレッドで行う。
- アスペクト比を維持し、nearest/linearの選択はRA画像ではlinear固定とする。
- 画像の取得でRA画面全体をブロックしない。

## 10. エラー表示

- 一時エラーはtoast、操作を継続できないエラーは確認画面で表示する。
- ユーザー表示には絶対パス、URI全体、HTTP POST本文、トークンを含めない。
- 診断コードを`RA-<domain>-<number>`形式で表示し、ログとの対応を可能にする。
- RA開始失敗後は「このセッションでは実績を取得できません」をゲーム開始時に明示する。
- オフラインセッション中は画面隅に常駐アイコンを表示し、オンライン表示へ途中変更しない。

## 11. Hardcore時のUI

- Hardcore中のフルオーバーレイは原則としてVMを止めずに表示する。
- 一時停止が必要な既存メニューへ移動する前に`rc_client_can_pause()`を確認する。
- 禁止操作は非表示ではなく無効表示し、選択時に理由を示す。
- Hardcoreを無効化する操作はゲーム終了確認を伴う。
- Androidバックグラウンド移行などユーザー操作で防げない停止は、状態を表示して
  `rc_client_idle()`へ切り替える。
- Offline sessionではHardcore表示を解除し、「Hardcoreは開始されていない」と明示する。

## 12. UIテスト条件

- 640x400、1280x800、縦長Android画面で文字・バッジ・操作列が重ならない。
- 最長タイトル、256バイトユーザー名、長い実績説明でも領域外へ描画しない。
- キーボードなしのAndroid端末でログインからゲーム起動まで完了できる。
- Controllerだけで全RA画面を移動・決定・取消できる。
- 画像未取得、破損、遅延時にもレイアウトが移動しない。
- Challenge、tracker、toast、ソフトキー、ステータス行を同時表示しても重ならない。
- VM映像が静止している状態でもtoastの表示・期限切れ、画像完了、scrollが再描画される。
- 不正UTF-8、4-byte UTF-8、Shift-JIS非対応文字でbuffer overflowや文字途中切断がない。
