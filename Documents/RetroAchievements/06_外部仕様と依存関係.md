# 外部仕様と依存関係

## 1. 基本方針

- RA通信と実績評価には`rcheevos`の`rc_client`を使用する。
- 公開Web APIを個別に組み合わせて`rc_client`相当の処理を独自実装しない。
- 外部依存はバージョンとcommit SHAを固定し、通常buildでネットワーク取得しない。
- 同梱したソース、ライセンス、変更内容を`ThirdParty/README.md`へ記録する。
- 依存更新は機能実装と同じcommitで行わず、専用commitとする。

## 2. `rcheevos`

### 2.1 固定バージョン

| 項目 | 値 |
|---|---|
| Repository | `RetroAchievements/rcheevos` |
| Tag | `v12.3.0` |
| Commit | `e9ca3694c862b61235595176dac4b22677848c93` |
| License | MIT |
| Integration API | `rc_client` |
| Console ID | `RC_CONSOLE_PC8800` (`47`) |

develop branchを直接取り込まない。tagとcommitの両方が一致することを取得時に確認する。

### 2.2 必須compile設定

- `RC_CLIENT_SUPPORTS_HASH`を定義し、production targetと公式hash比較testの双方へ
  `rc_hash`実装をlinkする。
- `RC_DISABLE_LUA`を定義し、Lua runtimeを同梱しない。
- HTTPS処理は`rcheevos`ではなく`RaHttpClient`が担当する。存在しないTLS compile optionを
  `rcheevos`へ追加しない。
- PC-88 whole-file hashに不要なdisc/encrypted/ZIP処理は、公式の依存関係を確認した上で
  除外可能とする。ただし初回統合では過度なsource削減を行わず、公式release構成を優先する。
- XM8 C++からincludeする公開headerは`extern "C"`対応済みのものを使う。
- release名はv12.3.0だが、この版の`rc_version_string()`はpatch 0を省略して`12.3`を返す。
  build testでは`rc_version()==12003000`かつ`rc_version_string()=="12.3"`を確認する。

source manifestは固定commitの`Package.swift`を基準とし、`include/`、`src/`、
`src/rcheevos/`、`src/rapi/`、`src/rhash/`のC sourceを列挙する。ただし
`src/rc_libretro.c`と`src/rc_client_external.c`はcompileしない。globだけに依存せず、
取り込んだsource一覧を`ThirdParty/versions.json`と同じcommitで記録する。

### 2.4 PC-88ハッシュ仕様

v12.3.0の`rhash`では`RC_CONSOLE_PC8800`は次の規則である。

- `.d88`: whole-file MD5
- `.m3u`: playlist先頭項目を解決し、そのD88をwhole-file MD5
- multi-image D88: 内部bankへ分割せずファイル全体をMD5

XM8側のMD5テストは公式`rc_hash`へ同じfixtureを入力し、文字列一致で検証する。
v12.3.0の公式M3U parserはUTF-8 BOMを除去しない。XM8はM3U pathを`rc_hash`へ渡さず、
XM8 parserが解決した先頭D88のMD5を`rc_client_begin_load_game()`へ渡す。BOM対応は
XM8の入力拡張として維持し、解決後D88のhashを公式`rc_hash`による直接D88 hashと比較する。
canonicalなBOMなしM3Uについてだけ、公式M3U hashとも一致を確認する。

### 2.5 PC-88メモリマップ

公式v12.3.0の公開マップに合わせる。

```text
0x000000-0x00FFFF Main RAM
0x010000-0x010FFF Text VRAM
```

XM8のGVRAMや拡張RAMを独自に後方追加しない。RA側の公式マップが更新された場合は、
依存更新とXM8メモリ公開を同じ変更セットで更新する。

## 3. SQLite

### 3.1 取り込み方法

- 公式amalgamationの`sqlite3.c`と`sqlite3.h`を`ThirdParty/sqlite/`へ同梱する。
- バージョンは安定版`3.53.0`へ固定する。
- GitHub mirror commitは`4ebc7fdcf459e8d88eb5b019c2949bda86565528`、
  Fossil source IDは`4525003a53a7fc63ca75c59b22c79608659ca12f0131f52c18637f829977f20b`とする。
- amalgamation archiveはSQLite公式配布物から取得し、SHA-256を
  `ThirdParty/versions.json`へ記録する。
- SQLite更新時はDB migration test、WAL、Android API 19 buildを再実行する。
- OS提供SQLiteと混在させず、全OSで同梱版を使って挙動を統一する。

### 3.2 compile設定

最低限、次を検討し、最終値をmanifestへ記録する。

```text
SQLITE_THREADSAFE=1
SQLITE_DEFAULT_FOREIGN_KEYS=1
SQLITE_OMIT_LOAD_EXTENSION
SQLITE_DQS=0
```

- loadable extensionを無効にする。
- FTSは初期検索要件に不要なため有効化しない。
- SQLCipherは使用しない。RA tokenはSQLiteへ保存しない。

### 3.3 ライセンス

SQLiteはpublic domainである。取得元とversionはthird-party noticeへ記載する。

## 4. `stb_image`

- `stb_image.h`を`ThirdParty/stb/`へ同梱する。
- `stb_image` v2.30を含むupstream commit
  `31c1ad37456438565541f4919958214b6e762fb4`へ固定する。
- 1つの`.cpp`だけで`STB_IMAGE_IMPLEMENTATION`を定義する。
- `STBI_ONLY_PNG`と`STBI_ONLY_JPEG`を定義する。
- `STBI_NO_STDIO`、`STBI_NO_HDR`、`STBI_NO_LINEAR`を定義し、画像buffer以外の入口を除外する。
- `STBI_MAX_DIMENSIONS`を2048に固定する。
- ファイルから直接decodeせず、上限検査済みメモリbufferからdecodeする。
- `stbi_info_from_memory()`で寸法を検査してから展開する。
- ライセンスはMIT/Public Domainのupstream記載を同梱する。

## 5. HTTP依存

### 5.1 共通要件

- TLS 1.2以上を利用する。OSがTLS 1.2を提供できない環境ではRA通信を無効化する。
- 証明書検証、hostname検証を必須とする。
- proxyは各OSの標準設定に従う。
- gzip等のcontent encodingはbackendで展開し、展開後サイズ上限を適用する。
- API bodyは`rc_api_request_t`が示すmethod、URL、content type、post dataを変更せず送る。
- `rc_api_request_t`にmethod fieldはない。`post_data==NULL`ならGET、非NULLならPOSTとし、
  空POSTをGETへ変換しない。
- API redirectは追跡しない。画像GETだけHTTPS間で最大5回追跡する。
- badge/avatar URLは`rc_client`が返したHTTPS URLだけを受け入れる。
- API transport失敗は`rc_api_server_response_t.http_status_code`へ
  `RC_API_SERVER_RESPONSE_CLIENT_ERROR`または
  `RC_API_SERVER_RESPONSE_RETRYABLE_CLIENT_ERROR`を設定して返す。

### 5.2 Windows

- WinHTTPを使用し、`winhttp.lib`をlinkする。
- system proxyを使用する。
- callback contextにはrequest IDだけを保持し、`RaService`のraw pointerを非同期で保持しない。
- application shutdown時にsession handleを閉じてcallback完了を待つ。

### 5.3 macOS

- `NSURLSession`をObjective-C++ adapterから使用する。
- App Transport Securityを無効化しない。
- delegate queueから直接C++ UIを呼ばず、完了キューへ値をコピーする。
- Foundation frameworkは既存link設定を使用する。

### 5.4 Linux

- libcurl multi APIを使用する。
- CMakeで`find_package(CURL REQUIRED)`し、`CURL::libcurl`をlinkする。
- 配布AppImageへ必要なlibcurl依存を含めるか、配布先の最小要件として明記する。
- CA bundleはlibcurlの標準探索を使用し、XM8独自の古いbundleを同梱しない。

### 5.5 Android

- Java `HttpURLConnection`/`HttpsURLConnection`を使用する。
- ExecutorService上で実行し、JNIへstatus、headers、body、error categoryを返す。
- custom TrustManager、全許可HostnameVerifierを実装しない。
- API 19で利用できないmethodはSDK version guardを付ける。
- lifecycle終了時に接続をdisconnectし、executorをshutdownする。

## 6. Android JNI契約

Javaとnative間ではrequest全体をraw pointerで共有せず、64-bit request IDで対応付ける。

NativeからJavaへ渡す値:

- request ID
- method
- URL
- content type
- body byte array
- connect/read timeout
- response上限

Javaからnativeへ返す値:

- request ID
- transport result
- HTTP status
- response content type
- body byte array
- sanitize済みerror message

callbackはSDL main threadとは限らないため、JNI受信関数は完了キューへコピーするだけとする。

## 7. ビルドシステム

### 7.1 CMake

root `CMakeLists.txt`へ次を追加する。

```cmake
option(XM8_ENABLE_RETROACHIEVEMENTS "Enable RetroAchievements support" OFF)
```

- RA ON時だけ`Source/RA`とthird-party static librariesを追加する。
- test targetからRA coreを再利用できるよう、RAコードをobject/static library化する。
- macOSは`.mm`、Windows/Linuxは該当platform sourceだけを選択する。
- LinuxだけCURLをrequiredとする。
- 対応済みOSの配布scriptは`-DXM8_ENABLE_RETROACHIEVEMENTS=ON`を明示する。未着手OSと
  通常の開発buildはOFFを既定とする。

### 7.2 Windows Visual Studio

- `.vcxproj`と`.filters`へRA、rcheevos、SQLite sourceを明示追加する。
- `XM8_ENABLE_RETROACHIEVEMENTS`をconfiguration propertyで切替可能にする。
- WinHTTP linkをRA ON時だけ追加する。
- source globへ依存しないため、CMake変更だけで完了とみなさない。

### 7.3 Android

- 現行Gradleのactive native build入口は`externalNativeBuild.ndkBuild`である。まず
  `jni/src/Android.mk`へRA sourceとstatic libraryを条件付き追加する。
- repository内の`app/CMakeLists.txt`もsource parityを維持する。実build入口として
  復活させない場合でも、RA ON/OFFの静的構成検証対象とする。
- Gradle property `XM8_ENABLE_RETROACHIEVEMENTS`をnative defineへ渡し、既定falseとする。
- Java sourceとJNI登録をrelease minify設定で削除されないようにする。
- rcheevosとSQLiteをnative `main`へ静的linkする。
- 全対象ABIで16KiB page size要件を維持する。
- `INTERNET` permissionをmanifestへ追加する。既に存在する場合は重複させない。
- Android Auto Backup/Data Extraction Rulesを追加し、internal filesとexternal app filesの
  `ra/`全体をbackup/device-transfer対象から除外する。

## 8. Feature flag

RA無効buildでは次を満たすこと。

- `Source/RA`をcompileしない。
- rcheevos、SQLite、HTTP backendをlinkしない。
- RAメニューを表示しない。
- `ra/`ディレクトリを作成しない。
- 既存setting/state形式を変更しない。
- RA用Android Java/JNIを呼び出さない。

RA有効buildでもruntime既定値はRA OFFとする。

`ThirdParty/versions.json`を追加し、最低限次を保持する。

```json
{
  "rcheevos": {
    "version": "12.3.0",
    "tag": "v12.3.0",
    "commit": "e9ca3694c862b61235595176dac4b22677848c93",
    "license": "MIT"
  },
  "sqlite": {
    "version": "3.53.0",
    "commit": "4ebc7fdcf459e8d88eb5b019c2949bda86565528",
    "source_id": "4525003a53a7fc63ca75c59b22c79608659ca12f0131f52c18637f829977f20b",
    "archive_sha256": "取得時に公式archiveの値を記録する",
    "license": "Public Domain"
  },
  "stb": {
    "version": "stb_image 2.30",
    "commit": "31c1ad37456438565541f4919958214b6e762fb4",
    "license": "MIT OR Public Domain"
  }

```

`archive_sha256`の説明文字列は計画書上の表現である。実際のmanifest作成時は
取得したarchiveの64文字小文字SHA-256へ置換し、説明文字列を残してはならない。

## 10. 依存更新手順

1. upstream release notesと公開header差分を確認する。
2. tag、commit、archive checksumを確認する。
3. clean sourceをvendor directoryへ反映する。
4. ローカル変更がある場合はpatchファイルとして分離する。
5. version manifestとthird-party noticeを更新する。
6. hash、memory map、`rc_client` API差分を監査する。
7. RA unit/integrationと、実装済みplatformを`macOS -> Windows -> Linux -> Android`の
   順でbuildする。
8. 既知D88で以前と同じhash/Game IDになることを確認する。
9. 依存更新だけのcommitとして記録する。

`rcheevos`更新でPC8800 hashまたはmemory mapが変わる場合は、通常の依存更新として
扱わず、ライブラリ互換性と既存RAセットへの影響を確認する別計画を作る。

## 12. ライセンス確認

- repository rootにはGPLv2本文がある一方、同梱xBRZ sourceにはGPLv3表記がある。
  XM8配布物全体を単純に「GPLv2」と断定せず、既存コードのライセンス適合性と配布表示を
  Phase 1で監査する。RA対応は既存のライセンス状態を悪化させてはならない。
- MITの`rcheevos`と`stb`、public domainのSQLiteはソース同梱とnoticeを行う。
- libcurlはcurl licenseに従う。
- OS frameworkは各OS SDKの条件に従い、third-party sourceとして同梱しない。
- release artifactにはXM8 LICENSE、rcheevos LICENSE、stb license記載、SQLite由来表示、
  libcurl noticeを含める。
