# RAステートメニュー分離実施記録

## 1. 目的

2026-07-20、NormalとRAで保存先が異なるにもかかわらず、Main menuの同じLoad／Save項目が実効modeに
応じて切り替わる曖昧さを解消した。保存形式やslot数は変更せず、操作導線だけを明確に分離する。

## 2. 確定仕様

- RA mode OFF:
  - Main menuにNormal用`Load State`／`Save State`を表示する。
  - RetroAchievements menuにstate項目を表示しない。
- RA mode ON:
  - Main menuのNormal用`Load State`／`Save State`を表示しない。
  - RetroAchievements menuにRA専用`Load State`／`Save State`を表示する。
  - slot画面titleを`RA Load State`／`RA Save State`とする。
  - slot 0を含む10 slotはすべて手動で、`(AUTO)`を表示しない。
  - ESCでslot画面からRetroAchievements menuの元項目へ戻る。
- RA stateを利用できない識別中、ゲーム未開始、管理媒体なしでは、RA専用項目を選択した時点で
  理由を通知し、slot画面へ進めない。
- Hardcore時のRA専用state項目非表示と全操作入口拒否はPhase 8で実効mode policyへ接続する。

## 3. 実装

- `Menu::EnterMain()`でRA mode ON時だけNormal用項目を省略する。
- `Menu::EnterRa()`でRA mode ON時だけRA専用項目を追加する。
- 共通slot描画は`EnterLoad(bool ra_state)`／`EnterSave(bool ra_state)`として再利用し、title、slot 0表記、
  ESCの戻り先を呼出し元に合わせる。
- `App::CheckRaStateAvailability()`で現在sessionとDrive 1のRA管理媒体をslot画面表示前に検証する。
- mode切替直後にRetroAchievements menuを再構築し、項目表示を即時反映する。

レビュー中、RetroAchievements menu IDの`1500..1599`が既存Joymapの同範囲と衝突していることを
確認した。RA IDを未使用の`2000..2099`へ移し、既存menu範囲との非衝突を`static_assert`で固定した。
これによりRA有効buildでJoymap commandがRA commandとして処理される潜在不具合も解消した。

## 5. 手動確認

1. RA mode OFFでMain menuにNormal用Load／Saveがあり、RA menuにはない。
2. RA mode ONへ切り替えるとRA menuにLoad／Saveが即時表示される。
3. Main menuへ戻るとNormal用Load／Saveがない。
4. RA専用Load／Saveのtitleに`RA`があり、slot 0に`(AUTO)`がない。
5. ESCでRA menuのLoad／Save項目へ戻る。
6. ASCEND識別後、既存RA stateをSave／Loadできる。

2026-07-20、利用者が上記の表示、遷移、Save／Loadを確認し、問題なしとして受入完了した。

## 6. 次回

次はPhase 8のHardcore policyへ進む。今回追加したRA state menuは、Hardcore実効session中に
非表示とし、menu以外のshortcutを含む全Save／Load入口も中央policyで拒否する。
